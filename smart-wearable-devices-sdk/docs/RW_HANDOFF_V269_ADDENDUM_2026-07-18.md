# RW handoff addendum v269

Build tag: `rw-visible-build-tag-20260718-271`

## 本次调整

- 确认前端 `/app/device/current` 请求来自公共设备绑定信息查询 `getBindInfo`，用于判断当前用户绑定设备，不是 RW BLE 协议命令，也不负责健康数据同步。
- `getBindInfo` 增加 5 秒短时缓存和并发去重。多个业务页面同时进入时，只复用同一次 `/app/device/current` 查询，减少前端日志和后端请求噪音。
- 保留原有本地缓存兜底：后端没有返回绑定设备、接口异常或旧后端不可用时，仍回退读取本地绑定缓存。
- 绑定和解绑后会清理短时缓存，避免页面继续使用旧的当前设备结果。

## 和 RW 数据同步的关系

- `/app/device/current` 只回答“当前绑定了哪台设备”。
- RW 数据同步仍由 BLE SDK 负责：连接设备、读取历史/实时数据、解析协议结果，再上传给后端。
- 因此后续排查 HRV、压力、体温、血氧、睡眠等业务数据时，应重点看 RW BLE 日志、历史上传日志和详情页后端查询日志，避免把 `/app/device/current` 误判成数据同步接口。
