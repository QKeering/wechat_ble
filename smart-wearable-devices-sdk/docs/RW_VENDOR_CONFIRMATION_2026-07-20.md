# RW/SY03 设备协议确认清单

测试设备：SY03  
设备 MAC / deviceId：`3E:00:00:00:05:1B`  
固件版本：`2.3.1`  
软件版本：`303e0001`  
BLE 通道：Service `0000A00A-0000-1000-8000-00805F9B34FB`，Write `0000B002-0000-1000-8000-00805F9B34FB`，Notify `0000B003-0000-1000-8000-00805F9B34FB`  
测试包标识：`rw-visible-build-tag-20260720-358`  
参考资料：设备商提供的协议文档和 APP SDK

## 1. 基础通信

以下命令已确认可以正常写入并收到设备回包，说明当前 BLE 连接、写入特征、Notify 特征可用。

| 项目 | 发送 hex | 设备返回 hex | 当前解析 |
| --- | --- | --- | --- |
| 电量读取 | `ab010003fca0020310` | `ab110006a38c0203106410d6` | 电量 `100%` |
| 电量续读 | `ab0100033c61020311` | `ab1100065f8d0203116410d6` | 电量 `100%` |
| 固件/软件版本 | `ab010003cca2020410` | `ab1100136b5502041002030100300040003330336530303031` | 固件 `2.3.1`，软件 `303e0001` |
| 设置设备时间 | `ab01000948030201001a07140a1f2f` | `ab11000350a0020100` | 设置成功 |

需要确认：

1. SY03 固件 `2.3.1` 是否推荐统一使用 `A00A/B002/B003` 这套 BLE 通道？
2. SY03 固件 `2.3.1` 是否统一使用 `AB` 帧格式进行读写？
3. 设备商提供的 APP SDK 是否适用于当前 SY03 固件 `2.3.1`？如果只适用于部分型号或固件版本，请帮忙标注适用范围。
4. 如果 APP SDK 中的 BLE 通道、包格式、命令字与 SY03 当前固件不一致，请以哪一份为准？
5. 除连接、开启 Notify、设置时间外，是否还需要初始化、登录、认证或开启采集等前置命令？

## 2. 睡眠数据

目前没有拿到有效睡眠 payload。以下命令均已在单独测试窗口验证，写入成功后等待设备回包。

| 项目 | 发送 hex / 命令 | 实际返回 |
| --- | --- | --- |
| 睡眠历史读取 | `ab0100039d12050510`，Key `0x0505`，Flag `0x10` | `ab1100039d12050510`，空 ACK，无睡眠 payload |
| 睡眠历史续读 | `ab0100035dd3050511`，Key `0x0505`，Flag `0x11` | 写入成功，8 秒无回包，超时 |
| 原始睡眠读取 | `ab0100036ce002fe10`，Key `0x02fe`，Flag `0x10` | 写入成功，8 秒无回包，超时 |

需要确认：

1. SY03 固件 `2.3.1` 正确的睡眠读取命令是哪一条？
2. `0x0505` 返回 `Len=3` 空 ACK 是否表示“当前没有睡眠数据”？
3. 如果 `0x0505` 只是第一步，后续应该继续发送什么命令？
4. 读取睡眠后，设备端睡眠数据是否会被删除或标记已同步？
5. 睡眠数据生成是否有前置条件，例如佩戴时长、入睡时间段、设备时间准确、睡醒后延迟生成等？
6. 请提供一条有效睡眠数据的完整发送 hex、完整返回 hex、字段解释和读取后的数据保留策略。

## 3. 步数数据

当前 `0x051a` 可以返回长包，但需要确认数据语义、时间戳和每日重置规则。

| 项目 | 发送 hex / 命令 | 实际返回 |
| --- | --- | --- |
| 当日活动/步数读取 | `ab010003ad1a051a10`，Key `0x051a`，Flag `0x10` | 返回长包，例如 `ab1100a30063051a10...` |

需要确认：

1. `0x051a` 的语义是“当天累计步数”、“每小时步数列表”，还是“第一条为总量、后续为小时记录”？
2. StepItem 中时间戳的计算方式是否为：小时粒度时间戳加上 `946684800` 得到 Unix 时间？
3. 步数字段长度、大小端和单位分别是什么？
4. 卡路里和距离字段的单位是否分别为：卡路里除以 10 得到 KCal、距离除以 10000 得到 Km？
5. 设备每日步数在什么时间点重置？是否严格按设备本地时间 `00:00` 重置？
6. 设置设备时间成功后，已有步数桶是否会重新归属到正确日期，还是只影响后续记录？
7. 是否存在更推荐的“今日步数”读取命令？请提供发送示例和返回示例。
8. 读取步数后，设备端历史步数是否会被删除或标记已同步？

4. `0x027d` 在 SY03 固件 `2.3.1` 上是否支持？

## 5. 心率、血氧、HRV、压力

心率和血氧实时数据已经拿到有效回包。HRV、压力需要确认设备侧原始值、单位和采集条件。

| 项目 | 发送 hex / 命令 | 实际返回 |
| --- | --- | --- |
| 实时心率 | Key `0x0224` | 例如 `ab11000943e5022400033328cc4600`，其中 `0x46 = 70` |
| 实时血氧 | Key `0x024e` | 已返回过 `97/98/99` 等有效值 |
| 心率历史 | Key `0x0503` | 无数据时返回空 ACK，例如 `ab1100033d11050310` |
| 血氧历史 | Key `0x0509` | 无数据时返回空 ACK，例如 `ab1100039d17050910` |
| HRV 历史 | Key `0x050a` | 需要确认有效 payload 格式 |
| 压力历史 | Key `0x050d` | 需要确认有效 payload 格式 |

需要确认：

1. 心率、血氧、HRV、压力的实时读取 Key 和历史读取 Key 分别是什么？
2. HRV 的单位、范围、采集频率和历史 payload 格式是什么？
3. 压力是否由设备端直接生成？如果是，正确 Key、单位、范围、等级定义是什么？
4. 心率/血氧/HRV/压力历史读取中，`Len=3` 空 ACK 是否统一表示“没有更多数据”？
5. 读取这些健康历史后，设备端数据是否会被删除或标记已同步？

## 6. 监测配置和设备能力

部分监测配置读取能返回，部分会超时，需要确认 SY03 固件能力范围。

| 功能 | Key | 测试结果 |
| --- | --- | --- |
| 心率监测配置 | `0x0216` | 曾返回 OK，但响应较慢 |
| 血氧监测配置 | `0x0225` | 曾返回 OK |
| HRV 监测配置 | `0x026a` | 曾返回 OK，但响应较慢 |
| 压力监测配置 | `0x026b` | 曾返回 OK |
| 体温监测配置 | `0x027d` | 超时 |
| 血压监测配置 | `0x027c` | 超时 |

需要确认：

1. SY03 固件 `2.3.1` 支持哪些监测配置？
2. 体温监测配置 `0x027d` 是否支持？如果支持，请提供 payload 和回包格式。
3. 血压监测配置 `0x027c` 是否支持？如果不支持，请明确标记为不支持。
4. 对不支持的功能，设备是否会超时不响应，还是应该返回错误 ACK？
